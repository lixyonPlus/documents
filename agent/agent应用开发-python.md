## 二、核心面试题 + 参考答案要点

> 用法：每题先记「答题框架」3-5 个关键词，面试时展开 1-2 分钟。不要背原文，要套你自己的项目。

### 模块 A：LLM 基础（必问，答不好直接减分）

**Q1. Transformer / LLM 生成的基本原理？Token、上下文窗口、温度是什么？**
答题要点：自回归逐 token 生成；上下文窗口是模型一次能处理的 token 上限，长对话要做截断/摘要/外置记忆；temperature 越低越确定（适合工具调用、抽取，设 0~0.3），越高越发散（创意写作）；top_p 与温度二选一调即可；还要提 token 成本意识——输入输出分别计价，长 Prompt 直接影响成本和延迟。

**Q2. 预训练、SFT、RLHF/DPO、LoRA 微调的区别？什么场景该微调，什么场景用 RAG/Prompt 就够？**
答题要点：先试 Prompt + few-shot → 不够上 RAG（知识会变、要溯源、企业私有数据）→ 格式/风格/领域术语始终不稳、且有高质量标注数据时才微调。微调改的是「行为和风格」，RAG 补的是「事实知识」，两者不替代。LoRA 只训低秩矩阵，显存省、可多适配器切换；QLoRA 再加 4bit 量化，单卡可训。

**Q3. LLM 幻觉产生的原因，怎么治理？**
答题要点：成因——训练目标是拟合语料不是求真、无实时知识、长上下文注意力稀释。治理分层：检索 grounding + 引用溯源；结构化输出 + 校验；低温度；不确定时澄清/拒答；关键事实走工具查询而非模型记忆；上线后抽检 + 评测集回归。**切忌只答「优化 Prompt」。**

**Q4. 流式输出、结构化输出怎么实现？**
答题要点：SSE/WebSocket 做 stream，首 token 延迟是体验关键指标；结构化输出用 JSON Schema / Function Calling 定义参数，由框架做校验（如 Pydantic），失败重试或修复；不要靠正则硬抠模型自由文本。

### 模块 B：Prompt 工程

**Q5. 一个生产级 System Prompt 怎么设计？**
答题要点：角色与任务边界、输出格式、工具使用规则、拒答/澄清策略、few-shot 示例、禁止事项。要版本化管理、能 A/B 测试、能按模型差异调优（JD 里明确有「针对不同模型调优 Prompt」）。示例要覆盖典型 + 边界 case，不要只给 happy path。

**Q6. Prompt 改了一版，怎么知道是变好还是变坏？**
答题要点：固定评测集（见模块 H），改前改后跑同一批 case，对比准确率/工具调用成功率/格式合规率；再小流量灰度看线上指标。凭感觉看几个例子不算数——这是面试官最爱追问的区分点。

### 模块 C：Function Calling / Tool Use / MCP（JD 高频）

**Q7. Function Calling 的完整链路是什么？工具调用失败/选错工具怎么办？**
答题要点：定义工具（名称、描述、参数 Schema）→ 模型决定调用并生成参数 → 应用层校验参数、鉴权、执行 → 结果回填上下文 → 模型生成最终回答。失败治理：参数校验与重试、工具描述写清适用/不适用场景、限制单轮最大调用次数防死循环、超时与降级、危险操作加人工确认（Human-in-the-loop）和审计日志。

**Q8. MCP 是什么？和普通 Function Calling / 插件有什么区别？**
答题要点：MCP（Model Context Protocol）是统一的工具/资源接入协议，把「工具怎么暴露、怎么发现、怎么调用」标准化，工具方实现 MCP Server，任何支持 MCP 的 Client/Agent 都能复用，避免每个 Agent 为每个工具写一套胶水代码。Function Calling 是模型层的能力，MCP 是系统层的协议，两者是配合关系。JD 里思灵机器人岗明确要求「基于 MCP 开发供大模型调用的工具」。

**Q9. 工具越来越多（几十上百个）时，怎么保证选工具的准确率？**
答题要点：工具分组/路由（先意图识别再在子集里选）、工具检索（用 embedding 按 query 召回 Top-K 工具）、合并同类工具、描述里写清边界和反例、评测集专门测工具选择准确率。

### 模块 D：RAG 全链路（重中之重，必深挖）

**Q10. 完整画一条 RAG 链路，并说每一步会怎么翻车。**
答题框架：文档解析 → 切分 Chunking → Embedding → 向量库索引 → 查询改写 → 召回 → Rerank → 拼上下文 → 生成 + 引用。
翻车点：PDF 表格/扫描件解析丢内容；切块太碎丢语义、太大引噪声；Embedding 模型与领域不匹配；只用向量召回漏关键词（要混合检索 BM25+向量）；无 Rerank 时相关文档排不进上下文；上下文塞太满导致中间遗忘（Lost in the middle）。

**Q11. Chunking 怎么切？怎么选 Embedding 模型和向量库？**
答题要点：按文档结构切（标题/段落）优先于固定长度，保留 overlap，表格和代码整块保留，带元数据（来源、时间、权限）。向量库选型：Faiss 适合本地/离线，Milvus 适合大规模分布式，pgvector 适合已有 PostgreSQL、不想多维护一套系统（JD 里讼牍科技就用 pgvec）。选型要答出数据量、运维成本、过滤需求三个维度。

**Q12. RAG 效果不好，你的排查顺序？**
答题要点：先分清是「没召回」还是「召回了没用好」——看检索结果里有没有正确答案文档。没召回：改切分、换 Embedding、查询改写/HyDE、混合检索、加 Rerank。召回了答错：改 Prompt 约束「只依据上下文」、调上下文排序与长度、换生成模型。**用评测集量化每步的 Recall@K 和最终答对率，不要盲调。**

**Q13. RAG 怎么处理权限、时效性和多轮对话？**
答题要点：召回时按用户权限过滤元数据，绝不能先召回再让模型「自觉不说」；文档更新做增量索引并标时间，过期文档降权；多轮要先做指代消解/查询改写，把「它多少钱」改写成独立完整的问题再检索。

### 模块 E：Agent 架构与编排框架

**Q14. ReAct、Plan-and-Execute、Reflection 有什么区别？怎么选？**
答题要点：ReAct = 边想边做（Thought-Action-Observation 循环），适合工具步数不确定的探索型任务，缺点是易绕圈、成本不可控；Plan-and-Execute = 先规划再执行，适合步骤明确的长任务，可控可并行，但计划错了要能重规划；Reflection = 执行后自评修正，适合代码、写作等可验证产出。生产系统常组合：Planner 拆任务 + Executor 用 ReAct 执行 + 关键节点校验。

**Q15. LangChain 和 LangGraph 的区别？为什么复杂 Agent 要用 LangGraph？**
答题要点：LangChain 是组件库 + 链式调用，适合线性流程和快速原型；LangGraph 用图 + 状态机建模，节点/边/条件分支/循环/中断恢复都显式，支持有状态工作流、Human-in-the-loop、断点续跑——JD 里法本、讼牍科技都点名 LangGraph 做「复杂有状态工作流」。答题时要讲清你项目里的 State 里存什么、节点怎么划分、失败分支怎么走。

**Q16. Agent 的记忆怎么设计？短期记忆和长期记忆分别怎么做？**
答题要点：短期 = 当前会话上下文（滑动窗口 + 摘要压缩）；长期 = 跨会话的用户偏好/历史事实存数据库或向量库，按需召回注入。关键坑：记忆写入要筛选（不是什么都记）、要有遗忘/更新机制、敏感信息不入长期记忆、记忆召回要做相关性过滤否则污染上下文。

**Q17. Agent 死循环、成本爆炸、一步错步步错，怎么防？**
答题要点：设最大步数/最大 token/超时熔断；每步做结果校验，失败走重试/换工具/降级到人工；关键动作前加确认；全链路 tracing 记录每步的 Prompt、工具参数和耗时，出问题能复现；任务拆解粒度适中，过碎易累积误差，过粗不可控。

### 模块 F：Multi-Agent 多智能体

**Q18. 什么时候真需要多 Agent？单 Agent + 多工具不够吗？**
答题要点：先答「能单 Agent 就别多 Agent」——多 Agent 带来通信、一致性、成本和调试成本。只有当角色专业分工明显（如研究员/写作者/审核员）、任务可并行、或需要相互校验制衡时才拆。协作模式：主管-下属（Supervisor）、流水线、辩论/投票。JD 里用 CrewAI 做多智能体协作、法本岗「主导多智能体架构」都是这个考点。

**Q19. Dify / Coze 这类低代码平台在团队里怎么定位？你怎么看？**
答题要点：适合快速验证、运营自助搭建、简单知识库问答；复杂状态、深度业务集成、性能与评测要求高时回到代码框架（LangGraph 等）。成熟团队常是双轨：平台做轻应用，代码做核心系统，两边共用模型网关和知识库。不要贬低也不要神化平台。

### 模块 G：微调与模型部署

**Q20. 做过垂直领域微调吗？数据怎么准备、效果怎么评估？**
答题要点：数据质量 > 数量，讲清洗、去重、格式统一、难例挖掘、训练/验证集划分；方法选 LoRA/QLoRA 并说明理由（成本、显存、迭代速度）；评估不能只看 loss，要用领域评测集 + 人工抽检 + 与基线（Prompt/RAG 版）对比，没赢过基线就不上线。

**Q21. 推理加速和降本有哪些手段？**
答题要点：模型路由（简单任务用小模型）、Prompt 缓存、批处理、量化、vLLM 等推理框架（PagedAttention、连续批处理）、控制上下文长度、缓存高频问答结果、流式输出优化体感延迟。答题给出你算过的一笔账：单次调用 token 量 × 调用量 = 月成本，面试官很吃这一套。

### 模块 H：评测、可观测、稳定性（区分初级与资深的关键模块）

**Q22. Agent 系统怎么建评测体系？LLM-as-Judge 靠谱吗？**
答题要点：离线评测集（真实场景采样 + 边界/对抗 case）+ 指标分层：检索 Recall、工具调用准确率、任务完成率、格式合规、人工满意度；LLM-as-Judge 便宜可规模化，但有位置偏好、自我偏好、评分漂移的坑，要用人工标注校准、双模型交叉或规则评测兜底。每次改 Prompt/换模型/改检索都要跑回归，设准入门槛。

**Q23. 线上 Agent 出问题，你怎么定位？**
答题要点：全链路 tracing（如 Langfuse / LangSmith / OpenTelemetry）看每一步输入输出、工具调用、耗时、token；按会话复现；区分模型问题、检索问题、工具/后端问题、Prompt 问题；有告警（成功率、延迟、成本异常）和降级预案（切小模型、关工具、转人工）。

**Q24. Prompt 注入攻击是什么？怎么防？**
答题要点：用户输入或被检索文档里藏指令，诱导模型越权（如泄露系统 Prompt、绕过权限调工具）。防御纵深：输入输出过滤、系统指令与用户数据隔离、工具最小权限 + 高危操作人工确认、检索内容视为不可信数据、敏感信息不进上下文。只答「过滤关键词」是不够的。

### 模块 I：后端工程功底（JD 里 Python/Java + MySQL/Redis/Spring 分量很重）

**Q25. Python 异步：asyncio 用在哪？Agent 服务为什么需要异步？**
答题要点：LLM 调用、工具调用、检索都是 IO 密集，异步 + 并发能显著提吞吐；讲清 event loop、await 阻塞点、同步库混入异步链路的坑、并发限流与超时控制。配合 FastAPI 做服务、流式接口。

**Q26. 高并发下 Agent 服务怎么做限流、缓存、幂等？**
答题要点：模型 API 有配额，要做队列/限流/重试退避；相同问题结果缓存、Prompt 缓存；工具调用尤其支付/下单类必须幂等（幂等键、去重表）；消息队列（Kafka/RabbitMQ）削峰和异步任务，讲至少一次投递与重复消费处理。

**Q27. MySQL / Redis 在你的 Agent 系统里分别存什么？**
答题要点：MySQL 存会话、用户、任务、审计等结构化数据（讲索引和事务）；Redis 存短期会话状态、缓存、限流计数、分布式锁；向量数据放向量库，不要硬塞 MySQL。Java 线的同学补：Spring Boot/Spring Cloud、MyBatis、服务治理同理迁移。

### 模块 J：系统设计题（3-5年岗位必考）

**Q28. 设计一个企业内部知识库问答 Agent（最经典，必练）**
答题框架（按顺序讲）：需求澄清（文档量、用户量、权限、延迟）→ 文档入库 pipeline → 混合检索 + Rerank → 带引用的生成 → 多轮改写 → 权限过滤 → 评测集与反馈闭环 → 成本与降级。主动提权限和溯源，加分很多。

**Q29. 设计一个能查订单、改地址、发起退款的客服 Agent，你怎么保证它不出事？**
答题框架：意图分流（咨询走 RAG、操作走工具）；操作类工具严格参数校验 + 二次确认 + 幂等 + 审计；超权限/低置信转人工；全程可回滚/可补偿；上线先影子模式再小流量。

**Q30. 从 0 到 1 让你负责一个业务 Agent，你第一个月做什么？**
答题框架：第 1 周吃透业务流程、拆任务图、定人机协同边界；第 2 周最小闭环原型（单 Agent + 核心工具 + 小评测集）；第 3-4 周接真实数据、补评测与 tracing、灰度给内部用户；用任务完成率而非「模型看起来聪明」验收。

## 四、行为面 / HR 面高频题（简答框架）

- **为什么从后端/算法转 Agent 方向？** —— 落点：原有工程功底 + 在现有栈上叠 AI 应用层，不要说「行业火、薪资高」。
- **和产品意见不一致（产品要全自动，你认为要人工兜底）怎么办？** —— 用风险分级和数据说话：先按场景分 L1-L4 自动化等级，高风险保留人工确认，灰度验证后再放开。
- **学习新框架的方法？** —— 官方文档 + 跑通最小例子 + 读一个关键模块源码 + 在项目里替换验证，给具体例子（如 LangGraph 的状态图）。

## 五、反问面试官（最后环节，别浪费）

1. 团队的 Agent 目前在哪个阶段：原型验证、内部使用还是已对外生产？主要业务场景是什么？
2. 模型选型是自研/微调为主，还是调用外部 API 为主？有没有模型网关？
3. 团队有没有评测集和 tracing 体系？这个岗位进来第一个要交付的项目是什么？
4. 这个岗位向谁汇报、和算法/产品怎么分工？

## 六、两周冲刺复习顺序（按 JD 权重排）

- **第 1-3 天：** RAG 全链路 + 向量库 + 混合检索/Rerank，能默画链路图
- **第 4-5 天：** Function Calling + MCP + 工具治理
- **第 6-7 天：** LangGraph 状态/节点/记忆 + ReAct/Plan 模式对比
- **第 8-9 天：** 评测体系 + 幻觉/注入治理 + 成本延迟优化
- **第 10-11 天：** Python 异步/FastAPI 或 Java/Spring + MySQL/Redis 复习
- **第 12-14 天：** 两道系统设计题口头演练 + 项目深挖 8 问逐字打磨 + 模拟自问自答
