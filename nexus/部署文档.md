# Sonatype Nexus Repository 3.97.3 稳定版安装目录与部署指南

> 版本：v1.0｜编写日期：2026-11-01  
> 场景：自建 GitLab + GitLab Runner + Spring Boot/Maven + 阿里云 ACK/ACR  
> 推荐：Nexus Repository Community Edition（CE）3.97.3 + 独立 ECS（Docker Compose）+ RDS PostgreSQL  
> 范围：安装目录规划、部署步骤、初始配置、Maven/CI 接入、备份与升级。以下为实施模板，**尚未在目标环境执行**。

## 1. 版本与部署决策

- **3.97.3**：2026-10-27 发布的 Nexus Repository 3.97.x GA 补丁版。镜像 `sonatype/nexus3:3.97.3` 有官方标签，生产应进一步固定镜像 digest。
- **Java**：官方镜像内置所需 Java 21，Docker 场景无需单独安装 JDK。
- **数据库**：Sonatype 推荐 PostgreSQL；官方明确说明**容器化运行不支持以 H2 作为数据库的部署**。使用外部 RDS PostgreSQL，从首次启动开始配置。
- **容量**：首期按 ECS **4 vCPU / 16 GiB**、数据盘按制品规模预留（例如从 100–200 GiB 起）估算；上线前根据并发、制品量、CI 构建频率和官方 sizing 指南调整。
- **CE 授权限制**：40,000 个总组件或每日 100,000 次请求；超过任一限额将阻止新增组件，需持续监控 Usage Center。
- **单机高可用性质**：独立 ECS + 单个容器不是 HA。需要 RDS 备份、数据备份、恢复演练和明确的停机窗口。

## 2. 推荐安装目录

### 2.1 ECS 主机目录（推荐）

```text
/srv/nexus/
├── compose.yaml                 # Docker Compose 编排（可纳入 Git）
├── .env                         # 含凭证，权限 0600，禁止提交 Git
├── .env.example                 # 无真实密码的环境变量模板
├── data/                        # 宿主数据目录 → 容器 /nexus-data
│   ├── blobs/                   # 制品/Blob Store
│   ├── etc/                     # Nexus 运行配置
│   ├── db/                      # 仅嵌入式 H2 情况存在；本方案使用外部 PostgreSQL
│   ├── log/                     # 日志
│   ├── tmp/                     # 临时文件
│   ├── keystores/               # 自动生成的密钥相关数据
│   ├── javaprefs/               # 持久化 Java preferences
│   └── admin.password           # 初始管理员密码；初始化后可能被移除
├── backups/                     # 导出备份（实际建议异盘/OSS）
├── scripts/                     # 备份、升级、巡检脚本
└── docs/                        # 运维文档、变更记录
```

> 以上 `data/` 中的子目录由 Nexus 启动后按需创建，并非都需要手工创建。目录 `backups/` 应优先使用**不同磁盘/OSS**，避免与生产 Blob Store 同盘故障。

### 2.2 官方容器内目录

| 容器路径 | 说明 | 是否应持久化 |
|---|---|---|
| `/opt/sonatype/nexus` | Nexus 应用安装目录，由镜像管理 | 否 |
| `/nexus-data` | 用户数据、配置、日志、制品 | **是** |
| `/nexus-data/blobs/` | 默认文件型 Blob Store 所在位置 | 是 |
| `/nexus-data/etc/` | 运行配置 | 是 |
| `/nexus-data/log/` | 应用日志 | 是/纳入集中日志 |
| `/nexus-data/admin.password` | 第一次登录所需密码文件 | 初始化使用 |

官方容器运行用户的 UID 为 `200`，宿主挂载目录应能被该 UID 写入。

### 2.3 传统 Linux 解压安装（非容器）的目录建议

```text
/opt/nexus/
├── releases/
│   └── 3.97.3/                 # 程序文件，版本化目录
└── current -> releases/3.97.3/  # 稳定入口软链接
/var/lib/nexus3/                 # 数据目录，独立持久化
/var/log/nexus3/                 # 可选：集中/软链接日志
/etc/systemd/system/nexus.service
```

**注意**：此处 `/opt/nexus/...` 是自定义安装规范，不是官方镜像内的路径。归档版默认 data-dir 通常是相对安装目录的 `sonatype-work/nexus3`，如果采用自定义数据目录需要同步配置运行选项。

### 2.4 ACK 部署的目录映射

```text
ACK StatefulSet/Pod
├── /opt/sonatype/nexus     # 镜像提供的程序文件
└── /nexus-data            # PVC 挂载目录（云盘）
    ├── blobs/
    ├── etc/
    ├── log/
    └── ...

外部：RDS PostgreSQL（同地域、低延迟）
```

ACK 必须使用持久化 PVC，不要使用容器临时目录或对数据安全要求较高的场景下的 `emptyDir`；单副本优先 `ReadWriteOnce` 云盘，调度时考虑可用区约束。**不推荐在同一个共享文件目录上简单增加多个 CE 副本。**

## 3. ECS 部署准备

1. 准备 Linux ECS，建议 4 vCPU/16 GiB 起评估；安装 Docker Engine、Docker Compose Plugin。
2. 连接 RDS PostgreSQL（同一地域/VPC 或低延迟私网网络），提前创建数据库 `nexus`，数据库用户是数据库 owner。
3. 仅开放必要端口：`8081` 不直接暴露公网，建议用 Nginx/内部 SLB + HTTPS 对外提供访问；RDS 只允许 Nexus 主机访问。
4. 预留磁盘与监控，文件型 Blob Store 需要可靠持久存储。

在 RDS 数据库管理员会话中按授权模型初始化（示例）：

```sql
CREATE ROLE nexus LOGIN PASSWORD 'REPLACE_WITH_STRONG_PASSWORD';
CREATE DATABASE nexus OWNER nexus ENCODING 'UTF8';
-- 切换连接到 nexus 数据库之后：
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

> 官方要求 Nexus 连接用户拥有目标数据库，用于自动建表和版本升级。某些 RDS 权限或扩展需要由数据库管理员完成；实际 SQL 应按实例已有角色与数据库情况调整。

## 4. 创建目录与权限

```bash
sudo mkdir -p /srv/nexus/{data,backups,scripts,docs}
sudo chown -R 200:200 /srv/nexus/data
sudo chmod 750 /srv/nexus/data
sudo chmod 700 /srv/nexus/backups
cd /srv/nexus
```

## 5. 准备环境变量

`/srv/nexus/.env.example`：

```dotenv
NEXUS_DB_URL=jdbc:postgresql://rds-postgres.internal:5432/nexus?sslmode=require
NEXUS_DB_USER=nexus
NEXUS_DB_PASSWORD=REPLACE_WITH_STRONG_PASSWORD
```

创建真实配置，禁止提交到 Git：

```bash
cd /srv/nexus
cp .env.example .env
chmod 600 .env
# 编辑 .env，填写真实的 RDS 内网地址与数据库凭证
```

> `sslmode=require` 能要求 TLS 加密，但不等同于完整的服务端证书身份校验；生产应配置 RDS CA 证书并优先采用 `verify-full`，同时验证镜像内的 Java truststore/证书链。

## 6. Docker Compose 部署配置

`/srv/nexus/compose.yaml`：

```yaml
services:
  nexus:
    image: sonatype/nexus3:3.97.3
    container_name: nexus
    restart: unless-stopped
    stop_grace_period: 120s
    ports:
      - "127.0.0.1:8081:8081"
    environment:
      NEXUS_DATASTORE_NEXUS_JDBCURL: "${NEXUS_DB_URL}"
      NEXUS_DATASTORE_NEXUS_USERNAME: "${NEXUS_DB_USER}"
      NEXUS_DATASTORE_NEXUS_PASSWORD: "${NEXUS_DB_PASSWORD}"
      INSTALL4J_ADD_VM_PARAMS: >-
        -Xms2703m -Xmx2703m -XX:MaxDirectMemorySize=2703m
        -Djava.util.prefs.userRoot=/nexus-data/javaprefs
    volumes:
      - /srv/nexus/data:/nexus-data
```

> JVM 内存值引用官方配置示例，并非适合所有负载的固定标准。ECS 需要给 JVM、堆外内存、OS Page Cache 和其他进程留有余量。生产建议将 `.env` 中的数据库密码改由受控 Secret/配置管理系统注入，避免长期保存在普通文件中。

## 7. 启动与验证

```bash
cd /srv/nexus

docker compose config --quiet
docker compose pull
docker compose up -d

docker compose ps
docker compose logs -f --tail=100 nexus

# 仅用于主机本机验证（容器启动可能需要数分钟）
curl -I http://127.0.0.1:8081/

# 获取首次登录密码（仅管理员查看）
sudo cat /srv/nexus/data/admin.password
```

管理界面内部访问地址示例：`https://nexus.example.internal/`，使用 Nginx/SLB TLS 代理到本机 `127.0.0.1:8081`。

首次登录账号 `admin`，应立即修改初始密码、设置管理员邮箱、检查匿名访问策略并关闭不需要的权限。

## 8. 创建 Maven 仓库

进入 Nexus 控制台 → Repositories，确认或创建以下仓库：

| 仓库名称 | 类型 | 用途 |
|---|---|---|
| `maven-releases` | Maven2 hosted | 内部稳定版 JAR / POM |
| `maven-snapshots` | Maven2 hosted | 开发快照 |
| `maven-central` | Maven2 proxy | 代理 Maven Central |
| `maven-public` | Maven2 group | 聚合三个仓库，作为开发者统一下载入口 |

Group 的顺序应根据是否需要优先匹配内部依赖来设计，并通过实际依赖解析测试验证。Release 仓库建议禁止覆盖历史版本，发布账号和下载账号分离。

### 8.1 Maven 下载端 settings.xml

```xml
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0">
  <mirrors>
    <mirror>
      <id>nexus-public</id>
      <mirrorOf>*</mirrorOf>
      <url>https://nexus.example.internal/repository/maven-public/</url>
    </mirror>
  </mirrors>
  <servers>
    <server>
      <id>nexus-public</id>
      <username>${env.NEXUS_READ_USER}</username>
      <password>${env.NEXUS_READ_PASSWORD}</password>
    </server>
    <server>
      <id>nexus-releases</id>
      <username>${env.NEXUS_DEPLOY_USER}</username>
      <password>${env.NEXUS_DEPLOY_PASSWORD}</password>
    </server>
    <server>
      <id>nexus-snapshots</id>
      <username>${env.NEXUS_DEPLOY_USER}</username>
      <password>${env.NEXUS_DEPLOY_PASSWORD}</password>
    </server>
  </servers>
</settings>
```

### 8.2 Maven 发布端 pom.xml

```xml
<distributionManagement>
  <repository>
    <id>nexus-releases</id>
    <url>https://nexus.example.internal/repository/maven-releases/</url>
  </repository>
  <snapshotRepository>
    <id>nexus-snapshots</id>
    <url>https://nexus.example.internal/repository/maven-snapshots/</url>
  </snapshotRepository>
</distributionManagement>
```

使用受控 CI 变量注入不同凭证后发布：

```bash
mvn -B -ntp -s settings.xml clean deploy
```

普通微服务通常只需要从 `maven-public` 下载依赖并使用 Jib 推送应用镜像到 ACR；仅内部公共库、SDK、公司 Starter 等需要将 JAR 发布到 Nexus。

## 9. GitLab Runner 集成

- Runner Job 中使用 `settings.xml`，通过 GitLab CI/CD Variables 注入只读用户；仅发布 Job 使用写入用户。
- 将 `NEXUS_READ_PASSWORD` 与 `NEXUS_DEPLOY_PASSWORD` 设为 Masked；写入凭证同时设为 Protected，只允许受保护分支或 Tag 使用。
- CI 运行在 ACK 时应允许其私网访问 Nexus HTTPS 入口；配置 DNS 和企业 CA 信任，避免关闭 TLS 证书校验。
- 尽可能统一 Maven 私服入口，避免开发机、CI 分别从外网拉不同版本依赖。

## 10. 备份、升级与日常运维

### 10.1 备份原则

数据库元数据会引用 blob 数据，**必须设计数据库和 Blob Store 的一致性备份**，不能仅复制 `/nexus-data/blobs`，也不能仅做 PostgreSQL dump。

可采用维护窗口内：

1. 停止上游发布任务；
2. 停止 Nexus 容器，等待优雅退出；
3. 创建 RDS 数据库一致性备份 / 使用 `pg_dump -Fc` 导出；
4. 备份 `/srv/nexus/data` 并复制到异盘/OSS；
5. 启动 Nexus，验证 Maven 读取和上传；
6. 定期在隔离环境演练恢复，保存备份时间、版本和校验记录。

生产环境如需在线一致性备份，应以 Sonatype 官方 PostgreSQL 备份指引为准，不要只靠定时 `tar`。

### 10.2 升级方法

1. 阅读目标版本 Release Notes 的 Known Issues / Upgrade Guidance；
2. 完整备份数据库及 Blob Store；
3. 在测试环境验证镜像升级、索引和仓库读取；
4. 更新 `compose.yaml` 的版本 tag（及固定 digest）；
5. `docker compose pull && docker compose up -d`；
6. 验证版本、仓库读写、日志、性能和 CI；
7. 如果升级涉及数据格式迁移，**不能假设直接切回旧镜像就能回滚**，必须根据官方步骤恢复匹配版本的备份。

### 10.3 必设监控

- 服务可达性、HTTP 5xx / 延迟、CPU/内存、磁盘容量/IO、RDS 连接及备份；
- Blob Store 使用量、组件数量、每日请求数、清理策略；
- 证书有效期、异常认证、Job 构建失败率。
